# SBCのWi-Fiを会話用の主回線にする

Orange Piの `wlan0` を自宅ルーターへ直接接続し、USBはPCとの固定IP管理用に使います。
アプリ・会話モデル・Cloud側の機器認証情報は変更しません。

```sh
gar target wifi --workspace Local/GarMyFriend-OrangePiZero2W --transport ssh --json
```

専用画面でSSID、Wi-Fiパスワード、必要な場合は実機Linuxのパスワードを入力します。
チャットに秘密情報を貼ったり、PCの保存済みWi-Fiキーを取り出したりする必要はありません。
PCの現在のSSIDだけを候補として表示します。

PC側のUSB管理用IPが外れている場合はWindowsの管理者確認後に復元します。
対象は保存済みGUIDのRNDIS機器と、同じIPを持つ未接続アダプターだけです。
通信共有・ファイアウォール・PCの既定回線は変更しません。
Windowsの管理者確認とLinuxのsudo認証は別の権限です。

Wi-Fiの接続情報は実機の `/etc/netplan/60-gar-wifi.yaml` にroot所有・0600で保存します。
ロールバック用の旧設定も実機のroot専用ディレクトリ `/var/lib/gar-wifi/` だけに保存します。
PCのログ・JSON結果・Git・App配布物にはパスワードを保存しません。
機器は既存のSSH鍵とホスト鍵で照合し、認証情報は対話要求を待ってSSHの非TTY標準入力へ渡します。

Wi-Fiの自動接続を設定したうえで、既存USB設定の固定アドレスを残し、USBの既定経路とDNS指定を外します。
これにより、USBケーブルが刺さっていても会話用インターネット接続はWi-Fiを使います。
Wi-FiのDHCP経路metricは10。USBの管理アドレスは従来の `192.168.137.2/24` です。

設定後はWi-Fiインターフェースを指定したTLS付きHTTPS接続と、実際に選ばれる経路を確認します。
無線インターフェースを一度down/upして、再接続後も確認します。
失敗時は以前の設定ファイルに戻します。SBC再起動と実際の会話は別途確認します。

読み取り専用の接続・依存ソフト確認:

```sh
gar target wifi --workspace Local/GarMyFriend-OrangePiZero2W --transport ssh --check --json
```

この確認ではWindowsのアドレス修復やWi-Fi設定は行いません。
初回のUSBコンソール経路は `--transport serial` でも利用できますが、Linuxログイン・sudoの認証が必要です。
